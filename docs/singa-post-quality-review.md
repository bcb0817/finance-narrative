## 実装した動作

- `SINGA_QUALITY_POLICY_ENABLED=true` と `EDITORIAL_POLICY_ENABLED=true` が新方針。最初の7×24時間は全体2本/日、以降4本/日。初回の送信予約から期間を永続保存し、プレビューでは開始しない。
- 全投稿種別・速報・送信結果不明の予約を含めて共通上限を適用。最短3時間。同一銘柄は1日1本。投稿後30分の新規投稿禁止もこの間隔に含まれる。
- 画像は当日の投稿の半分以下。したがって当日の1本目は本文のみ。画像の公開権・出典・期間審査も維持。
- `generate_post(event, ticker, direction, evidence, last_posts)` は `post_text`（審査済みpacket付き）または `skip_reason` を返す。送信しない。方向保留、根拠なし、新事実なし、対象外イベントは生成前に除外。
- 価格変動・決算日程・規制・IPOの単一事実だけを扱う。本文は3文以内、冒頭20文字以内、根拠に沿った判断文。ラベル、保留テンプレ、URL、末尾ハッシュタグを禁止。ハッシュタグ最大1。
- **文字数はX重み付き140〜220として実装**。日本語の実文字140〜220ではない。Xの通常投稿上限280との両立を優先した。固定長のために事実や判断を水増しせず、不合格なら見送る。
- 直近5本との先頭40文字・銘柄/数値正規化後の本文類似度80%以上を除外。これは編集上の「骨格」の近似判定であり、意味構造の80%を厳密測定するものではない。nanoの定型感審査も併用。
- 定型感が不合格なら再生成せず破棄。数字は一次資料の根拠内にある表記のみ。mini生成、nano分類・審査、金融安全審査を維持。
- ETF日次バッチは内部観測とSQLite候補キューに変更。保留・期限切れ・休場・除外・根拠不足は送信しない。候補はnews実行時に同じ編集ゲートへ渡す。送信直前も期限切れを再確認。
- 同じ事実のキュー投入は冪等。取得日時だけが変わっても別候補にしない。方向CASHは売り推奨に変換せず中立。
- 日次レビューで24時間実績の中央値、件数、反応のあったイベント種別を集計。7日後、中央値が参照フォロワー数の半分未満ならシグナル枠を2→1に縮小。費用・安全条件・投稿上限は拡張しない。
- 7日後、実績がある場合は反応が確認されたイベント種別のみ採用。現在は文章の「型」ではなく**イベント種別単位**の保守的な近似。反応が全くなければ無投稿になり得る。統計的有効性や配信回復を保証しない。

## 未接続・制約

1. **受信返信の取得と1往復の自動返信は未実装**。既存のスレッド送信機能は受信返信対応ではないため流用していない。実装には受信ID・会話単位の重複防止、根拠付き返信生成、読み取り費用管理を接続する必要がある。今回は返信・追加API呼び出しを行っていない。
2. 現在のETF公開スナップショットには `editorialEvent` と一次根拠 `evidence` がない。今ある方向・目標比率から根拠を捏造しないため、この入力のままでは内部ログのみ。上流に新事実・source/url/excerpt/period/retrieved_at/public_allowed/is_primary/provider等を持つ検証済み根拠のアダプターを追加する必要がある。
3. 本文リンクなしを適用。必要時のURLリプライは未接続。内部にはURLと根拠を保存する。
4. 参照フォロワー数は `RECOVERY_FOLLOWER_REFERENCE=110`。実測フォロワー数ではない。計測不足を0として扱わない。
5. 価格予測・売買推奨は引き続き禁止。「書き手の判断」は確認できる材料の範囲・比較の判断であり、架空の個人経験を加えない。

## 切り戻し

`SINGA_QUALITY_POLICY_ENABLED=false`、`EDITORIAL_POLICY_ENABLED=true` にすると前回の編集方針（通常6/全体10/時2/通常30分）に戻る。ただし **ETF専用日次バッチも旧定型更新へ戻る**ため、切戻し時はETF日次ジョブを停止してから行うこと。両方falseにするとさらに旧処理へ戻るため推奨しない。予算帳簿・投稿履歴・不確定予約を消さない。
